## Adversarial and scope review

The tests alter the inverse, lift, quotient, modulus, and zero-modulus-row data.
The zero-row counterexample preserves the first three certificate identities
but is rejected by the fourth. A JSON status-spoofing regression confirms that
unknown input fields cannot propagate a claimed kernel-verification result.
Generated proofs also check the serialized kernel matrix and obstruction
modulus, transformed target, and row against the Lean certificate, rather than
trusting those JSON fields merely because the primary answer is correct.
Invalid certificates remain distinct from mathematical nonexistence answers.

Semantic checks: the challenge fixes standard loops and actual induced maps;
there is no existential classifier. Valid-certificate existence is selected,
preventing vacuity from an impossible certificate format. The selected positive
answer covers every source loop class, not just vectors that happen to be
generated by the producer. Its kernel parameters need not be unique. The source
syntax is winding vectors, not arbitrary computably presented continuous paths.

The mathematical existence proof uses classical Smith theory. The executable
solver does not call that noncomputable proof. Producer termination/correctness,
asymptotic cost, priority, and independent expert assessment are outside this
validation record.
